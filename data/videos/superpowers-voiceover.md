### Section 7: Beyond Specifications (0:51 - 0:59)

## Chapter 4: How It Works

### Section 8: The 7-Phase Pipeline (0:59 - 1:08)
"The core is a seven-phase mandatory pipeline. Brainstorm the design. Set up an isolated git worktree. Write a detailed implementation plan. Execute with sub-agents. Then review every line of code. Every single project flows through this. No shortcuts allowed."

### Section 9: Socratic Design (1:08 - 1:17)
"It starts with Socratic design. Before writing a single line of code, Superpowers asks what you're really trying to build. It asks clarifying questions, explores alternatives, presents the design in digestible chunks, and proposes two or three different implementation strategies for you to choose from."

### Section 10: Sub-Agent Development (1:17 - 1:25)
"Then comes sub-agent driven development. Fresh agents tackle each task with a two-stage review — first for spec compliance, then for code quality. Each agent gets a clean context so there's no accumulated confusion."

### Section 11: Agent Orchestration (1:25 - 1:34)
"Multiple agents can work in parallel across isolated git worktrees without merge conflicts. An orchestrator delegates tasks to worker agents while a dedicated reviewer catches issues before they ever land in the codebase."

### Section 12: Hours of Autonomy (1:34 - 1:42)
"The result? Claude can work autonomously for a couple of hours at a time without deviating from the plan you approved. That's not an assistant following prompts — that's an agent executing a structured engineering methodology."

## Chapter 5: Why It Works

### Section 13: Enforced TDD (1:42 - 1:51)
"And here's the secret weapon: enforced test-driven development. Superpowers doesn't suggest testing — it mandates red-green-refactor on every single task. Write a failing test, watch it fail, write minimal code to pass, then refactor. It will literally delete code that was written before the tests."
