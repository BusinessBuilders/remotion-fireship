# Five Simple Hacks to Build Websites With AI Design

**Topic:** Five Simple Hacks to Build Websites With AI
**Slug:** `five-simple-hacks-build-websites-with-ai`
**Format:** Standard wide Fireship composition
**Tone:** Punchy, practical, fast-moving

## Goal

Produce a long-form Fireship-style explainer that uses `data/videos/current.md` as the primary reference structure, while supplementing it with current research and source attribution. The finished video should feel broader than a single-tool walkthrough, but still preserve the transcript's "few high-leverage inputs dramatically improve output" momentum.

## Source Strategy

`data/videos/current.md` is the blueprint. It provides the narrative spine:

1. Start with the common failure mode: AI-built sites look generic.
2. Show that a few workflow changes fix that.
3. Move from setup and inputs into increasingly useful output quality improvements.
4. End with a result that feels branded, intentional, and shippable.

Supplementary research fills gaps that the transcript cannot safely provide on its own:

- current product names and availability
- pricing/access claims
- attribution for skills/workflow concepts where needed
- broader AI website-building practices so the title is truthful

## Recommended Structure

Use a builder-style arc with a sharper hook:

1. **Hook**
   Explain why most AI-generated websites look interchangeable and why the fix is not "better taste" but better inputs and workflow.
2. **Foundation**
   Cover setup and project framing: editor/tooling, working in a clean project folder, and defining persistent instructions.
3. **Hack 1-2**
   Show how reusable project instructions and design-focused skills improve consistency and visual quality.
4. **Hack 3-4**
   Show how brand assets, explicit references, and targeted prompts make the site feel custom instead of generic.
5. **Hack 5**
   Show how iterative refinement, constraints, and production-minded review turn a one-shot prompt into a usable website.
6. **Close**
   Summarize the five hacks and the main principle: AI is fast when the system is constrained well.

## Scene Mix

The long-form template should use a broad scene mix rather than repeating content cards:

- Content scenes for the core hacks and connective tissue
- Code scenes for command snippets or prompt/system-file examples
- Diagram scenes for workflow architecture
- Stats scene for adoption, speed, or productivity framing
- Quote scene for a punchy framing line or industry statement
- Comparison scene for "generic AI site" vs "branded workflow"
- Timeline scene only if the research produces a concise, useful evolution/history beat
